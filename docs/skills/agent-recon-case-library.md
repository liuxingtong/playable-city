# Skill：案例库驱动的拼接式方案讨论（衡复 / 可玩城市）

供 Agent 踏勘「深化讨论」环节使用。与《徐家汇数据分析完整手册》第四章 **物理层融合维度** 对齐。

## 案例标签维度（每条案例至少标一个主维度）

| 维度 key | 含义 |
|----------|------|
| `site_perception` | 场地感知 |
| `concept` | 概念维度 |
| `form` | 造型 |
| `space` | 空间 |
| `function` | 功能 |
| `technology` | 技术 |

> 当前使用纯六维 key：`site_perception` / `concept` / `form` / `space` / `function` / `technology`。

## 工作方式（强制）

1. **先读结构化案例包**：每条含 `id`、`title`、`summary`、主/次维度、适用条件。
2. **按需引用**：讨论中显式写「引用案例 id：xxx」说明为何与本地场地匹配。
3. **拼接而非单抄**：最终方案优先覆盖案例库定义的关键维度（通常每个维度至少选 1 条），说明 **组合逻辑**（谁解决什么问题、时序上谁先谁后）。
4. **转译**：输出用「本地语句」描述策略，避免照搬案例标题当方案名。

## 输出结构建议（主持人）

- 共识 / 分歧  
- **拼接方案**：按当前维度分段，每段写清「引用 id + 本地转译 + 与指标(E/S/AC/N_CD/N_OS/N09)的对应关系」  
- 现场核验清单  

## 数据文件

静态案例库：`data/agent-case-library.json`（可替换为真实项目库，保持字段一致即可）。
