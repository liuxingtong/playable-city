## 叙事框架：人机共生城市与认知潜力的激活

### 概念核心

当我们谈论「可玩城市」，不是在谈论将城市变成游乐场，而是在谈论一种**认知生态**：城市空间如何通过刺激、缓冲与引导，激活居民对自身所在之地的感知深度与探索意愿。

本研究的叙事核心是：**通过人机共生空间的营造，打造可玩城市，从而激活城市空间的认知潜力。**

「人机共生空间」在此不是互动装置，而是一种城市体验的**双重结构**：

**物理层**：通过城市更新，提升空间的可玩性——边界的渗透性、尺度的亲切感、历史文脉的可读性、感官体验的丰富度。

**虚拟层**：引入 **AI 伴游者**。它在虚拟世界中主动漫游，会 *reach out to you*——告诉你它在某处体验到了什么；你也可以将自己在物理空间中的感知传递给它。它会自动爬取你当前所在位置的网络数据，推送「此地可以关注什么、有哪些可以玩的方式」。物理世界和虚拟世界的可玩性在此交织：

> **你是机在具身世界里的外延；机是你在虚拟世界里的探索者。**  
> 通过 AR 媒介，真幻交互。

除了物理空间被动地刺激认知，你与虚拟世界伴游者的互动也在拓展认知的维度。你把物理世界里的感知告诉它，它给你回传在虚拟世界里的游历经历。

虚拟世界是真实城市的**镜像**，与物理坐标一一对应。用户可以开启「跟随模式」，让自己的**数字公民**（可自定义 avatar 的数字分身）随自己的物理移动在虚拟镜像中同步行动。数字公民之间可以相遇、互动，并在虚拟城市中协作搭建属于自己的世界。

> **注**：AI 伴游者与虚拟镜像的具体技术形态在设计阶段进一步定义；「跟随模式」与数字公民的交互功能是衡复改造方案的虚拟层提案。

## 第一章：人群认知——小红书数据与五类画像构建

### 1.1 数据来源与爬取逻辑

以**大徐家汇地区**（四街道并集，见 `data/daxujiahui-four-streets-union.geojson`）为空间范围，爬取小红书平台上与该地区相关的内容，通过话题聚类与行为模式分析，归纳出五类与该地区互动特征最鲜明的人群。

| 数据维度 | 内容 |
|---------|------|
| 地理锚点 | 大徐家汇范围内的地点打卡、地点提及 |
| 内容类型 | 图文笔记、话题标签、评论文本 |
| 分析方法 | 话题聚类、行为模式归纳、活动尺度推断 |
| 输出 | 五类人群画像（活动尺度、数字习惯、主要关切、叙事权重） |

五类画像是后续所有分析的**人视角锚点**：CPVI 选址用它们界定「谁被服务」，踏勘系统用它们驱动语义评分，设计方案用它们产出差异化的空间建议，CLD 仿真用它们构造五轴停留意愿雷达。

### 1.2 五类 Agent 画像

| 代号 | 画像 | 活动尺度与数字习惯 | 主要关切 | 叙事权重（相对优先级） |
|------|------|---------------------|----------|-----------------------|
| **Agent1** · 梧桐爷爷 | 65–80 岁本地老人 | **约 500 m 生活圈**；偏好「会说话的大屏」等低认知负荷触点，**回避复杂小程序** | 铺装、座椅、遮阴、厕所；菜场、药店等**拥挤度** | **适老友好** > **日常连续性** > **低门槛被动参与** |
| **Agent2** · 高校学生 | 18–25 岁；交大徐汇、上音等 | **数字原住民**；活动锚点含咖啡馆、黑石 M+、安福路等 | **社交货币**、可结伴玩、传播性（打卡/话题） | **社交传播** > **探索趣味**（非线性路径、彩蛋）> **群体互动条件** |
| **Agent3** · 商圈白领 | 28–40 岁；片区 **39 幢重点楼宇** | **午休约 1 h**、下班后衡山路等动线；时间预算紧 | **低时间成本**、不幼稚、**意外获得感**、**15 min 级解压** | **距商圈步行**（**500 m 午餐圈**）> **碎片化体验密度**（**5–15 min**）> **释压潜力** |
| **Agent4** · 遛娃家庭 | 30–45 岁父母 + **3–10 岁儿童**；徐汇、长宁及更远到访 | 单次停留 **1–2 h** | **安全**（人车分离、视线通透）、**教育性**（历史/自然/科技）、**持续吸引力**（可重复玩） | **安全** > **亲子共创空间** > **叙事深度**（**30 min+ 故事线**） |
| **Agent5** · 文艺漫游者 | 22–35 岁；City Walk / 内容创作者 | 弱固定锚点、强路径依赖 | **叙事密度**、转角惊喜、**非常规视角**、**出片条件** | **叙事密度** > **发现感** > **内容生产友好**（光线、背景、取景） |

**儿童视角（Agent4 专项，眼高约 1–1.5 m）**：踏勘与评估时应**单独代入儿童视线高度**——标识与导视的**视认高度**、栏杆与绿篱的**通透率**（是否挡视线）、游戏与互动节点的**蹲姿/低姿尺度**，避免仅以成人默认视线替代亲子体验；与上表「安全」「持续吸引力」权重直接相关。

### 1.3 五维雷达：停留意愿的空间投影

五类画像不只是叙事工具，也是空间评分的投影轴。对每条街段，依据七维共享特征（E、1−S、AC、N_UD、N09、N_CD、N_OS）按五套叙事权重合成五个 **Wp 分轴**，经验分位后形成**五维雷达**。雷达顶点越高 = 该类人群在此路段的停留意愿越强；五轴**非零和**，同一路段可对多类人群同时偏高。详见**技术附录 E**。

**Agent 踏勘 MVP**（第三章）在**同一七维**之上增加第八维 **N_OD**（轨迹 OD 网合成），再算五类 **Wp** 与分位雷达，口径见 **§3.5** 与 **附录 E.1** 踏勘扩展。

## 第二章：区域识别——CPVI 模型与大尺度选址

### 2.1 选址逻辑总述

从大徐家汇全域出发，用 CPVI 模型在路网边级识别**潜力节点**（人流大、认知需求强但缓冲资源不足）和**资源节点**（缓冲资源集中），再用 DBSCAN 将同类节点聚合成**潜力区**和**资源区**，并识别连接两类区域的**轴线**，由此框定几个值得进一步介入的大片区。

### 2.2 CPVI 模型：城市可玩-认知脆弱性指数

**核心公式**：

```
CPVI_i = (E_i × S_i) / (AC_i + 1)
```

| 分量 | 语义 | CPVI 高时的含义 |
|------|------|-----------------|
| **E（暴露度）** | 人流潜力大且文化接触需求强烈 | 此路段是认知刺激的理想投放地 |
| **S（敏感性）** | 机动车压力大、开敞空间少 | 认知负荷风险突出 |
| **AC（适应能力）** | 绿化缓冲 + 文化场所 + 舒适街道 | 分母低 → 几乎无认知缓冲，优先级最高 |

> 分数越高 → 人流潜力大、认知负荷风险高、缓冲资源不足 → **优先部署可玩接口**

各分量的具体计算公式见**技术附录 D**。

### 2.3 DBSCAN 聚类：资源区、潜力区、连接轴线

对 CPVI 结果做**触媒 DBSCAN**，将候选边（激活 ∪ 临界）聚合为空间簇：

| 输出类型 | 定义 | 可视化 |
|---------|------|--------|
| **潜力区** | CPVI 高档 × 至少一类人群 Wp 高档的簇 | 激活潜力点 |
| **资源区** | 五类主导 AC 各前 10% 的簇 | 资源节点（含文化/科技/商业/体育/交通主导子类） |
| **连接轴线** | 跨簇边（接缝边）构成的廊道 | 玫红折线（`field_system_selection.html`） |

DBSCAN 参数与廊道算法细节见**技术附录 E**。

### 2.4 大片区划定

根据聚类结果，在大徐家汇范围内框定数个介入优先级较高的大片区，作为**导则改造**的空间单元。每个片区基于其主导节点类型，拟定差异化的介入方向（文化激活型 / 慢行修复型 / 商圈渗透型等）。

衡复风貌区因其**历史肌理完整、社区-城市交界面丰富、五类人群共现程度高**，被确定为下一步精细选址的聚焦区域。

## 第三章：聚焦选址——衡复风貌区五类智能体踏勘

### 3.1 研究范围与选址目标

从第二章识别的大片区中，聚焦**衡复风貌区**，目标是在其中找到约 **5 公顷**的改造选址。这一阶段引入**五类智能体踏勘系统**——一套以 AI Agent 驱动的多维度语义评分框架，替代或补充传统人工踏勘。

### 3.2 在地访谈与画像补充

在衡复风貌区内，按五类画像招募对应人群进行访谈，获取：

- 空间感知的描述性语言（「这里让我感到…」）
- 典型活动路径与停留点（手绘地图 / GPS 轨迹）
- 对「可玩」的理解与期望（行为意图 vs. 现实障碍）
- 对虚拟层介入（AI 伴游者）的接受度与使用场景设想

访谈结果作为**补充训练数据**，注入五类 Agent 的语义权重，使其在图像分析时更贴近各类人群的实际感知逻辑。

### 3.3 五类智能体踏勘系统

基于补充后的画像，构建五类 Agent，读取衡复风貌区的街景与现场图像。下表为**叙事与访谈对齐的语义维度**（用于理解「在看什么」）；**工程上的规则分**仍以与附录 E 一致的 **CPVI 相关七维 + 轨迹网 N_OD** 构成特征向量（见 §3.5、附录 E.1 踏勘扩展），可选 **智谱 GLM** 对街景给出 0～1 辅助分并与规则分位加权合成。

| 维度 | 描述 | 关联画像 |
|------|------|---------|
| **社区-城市交界面** | 该地块是否处于社区内部与城市公共界面的过渡带；围墙、绿篱、底层界面的渗透性 | 全体 |
| **空间尺度与围合感** | 开敞/半围合/围合的空间特征；D/H 比例；与人体尺度的关系（叙事参考；踏勘页矩阵**不**单独增列，街景模型提示已从简） | Agent1（宜人尺度）、Agent4（视线通透） |
| **历史文脉可读性** | 建筑风貌层叠、街道标识、时间层次的可辨认程度 | Agent5（叙事密度）、Agent2（打卡价值） |
| **可玩性潜力** | 边界模糊度、停留邀请感、非线性路径可能性、儿童可达性 | Agent4（儿童安全）、Agent3（碎片化体验） |
| **人群活动痕迹** | 街景中自发占用等**表象**仍可由模型描述；**定量**侧由轨迹样本构建地块 **OD 网**（相邻停留点有向边，边权为轨迹频次），计算 **介数中心性**、**调和接近性（整合度）**、**边权 PageRank**，合成 **N_OD** 并入规则特征（见 §3.5） | Agent1（日常连续性）、Agent5（发现感） |

每类 Agent 的**规则改造优先级 proxy** 来自加权特征经样本内 min–max 后的 **Wp** 与经验分位 **p_***；启用视觉模型时，单 Agent **综合分 = 0.35×街景分 + 0.65×p_***（权重见 `lib/agent-recon-mvp.js` 常量）。

### 3.4 三个优先地块的选出

综合五类 Agent 的评分结果，以「五类人群加权均分最高 × 社区-城市交界面类型最丰富 × 与 CPVI 潜力节点空间重叠度最高」为筛选标准，从衡复风貌区内选出**三个改造优先地块**，进入设计阶段。

### 3.5 工程实现、外部案例库链路与一键启动

五类智能体踏勘的**可运行实现**在本仓库 **`pages/agent-recon-mvp.html`**（脚本 **`lib/agent-recon-mvp.js`**）。

**勘探范围**：默认以 **`data/tianping-road-street.geojson`**（徐汇区天平路街道）裁剪边段与街景索引；聚焦 **衡复风貌区** 时，请自备与 WGS84 对齐的多边形 GeoJSON，通过 **`window.AgentReconStudyConfig.boundaryUrl`**（及可选 **`label`**）或 URL 参数 **`?boundary=../data/xxx.geojson`** 切换（路径相对 `pages/` 下页面）。细节见 **`docs/agent-recon-contracts.md`** §3。

**轨迹活动指标**：`npm run build:block-od` 读取 **`data/徐汇地块轨迹样本_工作日.xlsx`** 与 **`data/徐汇地块轨迹样本_周末.xlsx`**（轨迹键为「文件名|rn」以避免 rn 重号），生成 **`data/block-od-activity.csv`**；踏勘页将每条边中点与最近地块质心匹配，写入 **N_OD**（距离超阈值则取中性 0.5）。若文件缺失，**N_OD** 恒为 0.5。

## 第四章：设计方案——人机共生空间

### 4.1 头脑风暴与参照来源（网页检索默认，案例库可选）

针对三个优先地块，让五类智能体进行**跨人群头脑风暴**——从各自关切出发，碰撞出既满足个别需求又产生共现价值的空间策略。**默认**通过本地 **网页检索代理**抓取公开网页摘要，为方案提供可核查的参照链接与片段；将前端 **`ragProxyUrl`** 切回案例库代理端口后，仍可对接独立 **case-base** 向量库，获得 **`compose_id` / `event_id` / `trace_id` / `refs`** 等可追溯字段，并由 **SSE** 推送 **`case_ids`** 供界面短时高亮（**SSE 或回放失败不影响主回答返回**，见 **`docs/agent-recon-contracts.md`** §6）。

工程上，页面始终合并本地 **`data/agent-case-library.json`**（六维结构化预选）与讨论 Skill；深化链路的「多维检索」与 **六维 key** 对齐（见 §4.2）。需**单独的知识图谱式浏览与可视化**时，使用 **建筑灵感知识图谱 archgraph**（外部案例库专用前端，见 §3.5 表末行）。

### 4.2 物理层：空间可玩性提升（模数空间单元盒子 + 垂直广场拓展脚手架）

物理层**不再要求**五类 Agent 输出一份「完整建筑设计方案」或长篇推导，而是各自基于踏勘与叙事权重，提出可落地的 **空间单元盒子**——作为**插入件**，挂载在**配套结构原型「动态方格垂直广场 · 拓展脚手架」**上（该原型与本研究叙事并列记入本手册，工程实现可为独立仓或同工作区子项目，以结构/交互深化为准）。

#### 产出形态：空间单元盒子（12 m 模数）

- **基本模数**：每个盒子取 **12 m × 12 m** 的平面占位（柱网与荷载假设与脚手架协调，不在此展开）。  
- **扩展**：若某类活动需要更大连续场地，可按 **12 m 整数倍** 拼合（如 24×12、24×24），仍视为同一「逻辑盒子」或一组相邻插入单元。  
- **描述粒度**：每位 Agent 用**较短篇幅**说明——建议 **1～3 个盒子** 即可，每个盒子交代：**模数组合（几×几格）**、**意向功能 / 时段**（如午后停留、夜间展演）、**与核心筒或桁架的关系**（贴筒、跨格、占角等）、**若引用检索**则附 URL 或 case id。  
- **主持人汇总**：压缩为 **盒子清单 + 拼贴关系 + 与脚手架层位/幕墙状态的配合**（不必重复完整方案逻辑）。

#### 配套项目摘要：动态方格垂直广场 · 拓展脚手架

下列内容为**承载模数盒子的母结构**之设计意图汇总，供 Agent 输出时默认对齐（避免每人重新定义结构体系）：

| 子系统 | 要点 |
|--------|------|
| **整体意象** | 由**动态方块**叠合而成的**垂直广场**——竖向多层，体块可感知地参与空间划分与时间性使用。 |
| **楼层面格网** | 每层板面划分为大量 **1.2 m × 1.2 m** 的方格位；格位在**竖向可升降/可变速**，随**不同时段人群活动**改变标高，**自然形成**凹坑、台地、围合或通廊等微区域，而非固定家具摆场。 |
| **幕墙策略** | **内外圈幕墙**可**联动开合**：**白天**尽量**打开**，利于观光、渗透与城市界面可读；**夜间**可**收合为连续幕布**，作为**大面投影**载体。 |
| **结构体系** | **钢桁架**承担大跨与悬挂/承托可变格板；**核心筒**内集中 **楼电梯 + 卫生间**，作为垂直交通与服务锚点。 |
| **内区与扩展** | 桁架**内圈围合**区域可作为**活动广场**或主聚集腔体；**桁架向外延伸**时，可继续**接入模数化插入空间**（与 **12 m×12 m** 盒子及倍数扩展对接）。 |

Agent 的 **12 m 模数盒子**即设计为**挂接在该脚手架上**的模块：可指明占用的**方格阵列范围**（以 1.2 m 格为最小语义单位、12 m 为与桁架/运输逻辑对齐的推荐单元）、以及希望配合的**幕墙开闭状态**（如夜间投影面、白天通透面）。

#### 六维检索与盒子输出的对应（精简）

头脑风暴仍可按 **六维 key** 组织检索与发言（与 **`lib/agent-recon-dimensions.js`**、案例库一致），但**正文以盒子为主**，维度仅作**标签式对齐**，避免长篇论证：

| 维度 key | 名称 | 盒子输出中常对应的落点（示例） |
|----------|------|--------------------------------|
| **site_perception** | 场地感知 | 盒子回应的身体尺度、压迫/通透感、与街景记忆的关系 |
| **concept** | 概念 | 想用这个盒子表达什么观念 |
| **form** | 造型 | 盒子体量组合、界面开合与视觉重量 |
| **space** | 空间 | 想营造什么样的空间体验与氛围 |
| **function** | 功能 | 花园？餐厅？书吧？或者其他。想承载什么样的人群活动？ |
| **technology** | 技术 | 材料？结构？细部构造？ |

网页检索以 **URL / 标题** 追溯；案例库以 **case id** 追溯。最终由人工对**盒子与脚手架的接口可行性**及风貌协调做裁断，不要求在本阶段闭合全部工程细节。

### 4.3 虚拟层：AI 伴游者系统

#### 概念

AI 伴游者不是装置，也不是导览 app，而是一个**陪你一起游历这个世界的虚拟伙伴**：

- **主动 reach out**：它在虚拟世界中漫游，会主动向你发送它在某处经历的感受与发现
- **双向感知传递**：你可以把在物理空间中的体验（看到的、听到的、感受到的）告诉它，它将其纳入自己的虚拟游历
- **在地数据推送**：自动爬取你当前所在位置的网络数据，告诉你「这里现在有什么可以关注、有哪些可以玩的方式」

#### 虚拟世界：真实世界的镜像

虚拟世界不是独立构建的抽象空间，而是**真实城市的镜像**——与衡复风貌区的地理坐标一一对应，街道、建筑、开放空间在虚拟层中都有对应的存在位置。

用户可以启动**「跟随模式」**：数字公民随自己在物理世界的移动路径，同步在虚拟世界的对应坐标上行动。你走进一条弄堂，数字公民也进入虚拟镜像里的那条弄堂；你在某个转角停留，它也在虚拟层的对应位置驻足，感知并积累该地点的虚拟信息。

#### 媒介与交互形式

通过 **AR 媒介**实现真幻叠加：物理空间中的地点成为虚拟伙伴游历的「传送门」，现实与虚拟在同一坐标系下相互注释。你的物理感知与数字公民的虚拟体验在 AR 界面中叠合、对话。

与 **§4.2** 物理层的 **12 m 模数空间单元盒子** 叙事衔接：盒子亦可理解为 **AI 在感知真实世界之后、希望在此地落成的建造愿望**——伴游者在虚拟镜像中的游历与推断，以盒子的占位、组合与功能意向在 AR 中与现场叠合，使人既能看见地貌与文脉，也能看见「机在此地想为你盖什么」；最终仍由人与设计流程对盒子与脚手架做裁断。

#### 数字公民与虚拟社群（衡复改造功能提案）

每个用户都拥有自己的**数字分身（数字公民）**：可以自行设定 avatar 外观与性格，携带自己的感知记录与游历轨迹。数字公民之间可以**相互交互**——在虚拟镜像城市中相遇、交换各自的游历体验、共同在某个地点留下标记，乃至**协作搭建虚拟世界的局部内容**。

| 功能层 | 描述 |
|--------|------|
| **个人层** | 设定 avatar、记录物理游历轨迹、积累虚拟探索内容；可启动**跟随模式**——数字公民与用户物理位置同步，实时在虚拟镜像对应坐标行动 |
| **社交层** | 数字公民之间相遇、互动、交换体验片段 |
| **共建层** | 多个数字公民协作，在虚拟城市镜像的地理坐标上搭建共享的叙事内容与虚拟空间 |

这四个功能层是衡复改造方案中虚拟层的具体功能提案，将在设计深化阶段明确技术实现路径。

## 第五章：效果验证与迭代——CLD 回路与 SD 仿真

### 5.1 验证逻辑

改造完成后，通过 **CLD 因果回路图 + SD 系统动力学仿真**，判断改造方案是否对本研究概念关注的核心指标产生提升。这一步不只是评估，也是**迭代优化**的起点：仿真结果反馈到选址与设计环节，形成可复用的设计系统。

### 5.2 核心研究发现（CLD 基础）

CLD 模型揭示三条核心发现，是「可玩城市」理论的支撑依据：

1. **文化认知回路**（R1）：经常接触艺术文化场所可以系统性促进认知恢复——提升文化场所密度 N_CD 与街道界面活跃度 N_SI，长期驱动城市可玩性指数 N_UV
2. **密度-复杂性注入**（R2）：高密度城市的声音与视觉复杂性本身是认知刺激的来源，而非纯粹威胁；需要通过可玩接口（N_PI）将其转化为正向体验
3. **开敞空间缓冲效应**（R3）：当高密度空间中镶嵌有认知缓冲型开敞空间（N_OS）时，其长期保护作用远胜于缺乏连接的低密度郊区

### 5.3 人机干预的仿真机制

人机干预（N_HM，对应物理层改造 + 虚拟层 AI 接口部署）**不改变 CLD 拓扑**，只改变边的传递函数参数：

| 边 | 修改内容 |
|----|----------|
| N_HM → N_PI | 激活可玩接口密度，从 0 到正值 |
| N14 → N_CR | 倒 U 型峰值右移（系统能承受更高认知复杂度） |
| N_PI → N_BD | 互动行为数据密度上升，驱动 R_play 回路 |
| N_BD → N_OPT | 干预优化持续改善可玩接口布局 |

6–9 个月出现相变点：N_PI 达临界密度后自我强化，R_play 与文化认知回路（R1）产生协同效应。

### 5.4 关键监测指标

| 指标 | 含义 | 目标方向 |
|------|------|---------|
| **N_UV** | 城市可玩性指数 | ↑ 改造后提升 |
| **N_CR** | 认知恢复潜力 | ↑ 缓冲资源增加 |
| **N_PI** | 可玩接口密度 | ↑ AI 接口落位后激活 |
| **N_CL** | 认知负荷 | ↓ 机动车压力缓解 |
| **Wp_*** | 五类人群停留意愿分轴 | ↑ 各类人群均有改善 |

### 5.5 可复用设计系统

验证形成的模型参数与空间策略组合，沉淀为可复用的设计导则：对不同区位类型（社区-城市交界面型 / 历史肌理型 / 商圈渗透型等）给出差异化的介入策略包，供后续同类地块直接调用。

#### B.2 街景衍生指标

| 指标 | 含义 | 计算方式 |
|------|------|----------|
| GVI | 绿视率 | vegetation + terrain |
| SVF | 天空可见度 | sky |
| Shade_Comfort | 遮蔽舒适度 | (vegetation + building + bridge + tunnel - sky) 归一化 |
| Motor_Pressure | 机动车压力 | car + bus + truck + motorcycle + road |
| Shannon_H | Shannon 多样性 | -Σ(pᵢ·ln(pᵢ))，按 7 大语义类别 |
| Complexity | 视觉复杂度 | 非零类别数 × Shannon_H，归一化 |
| Ped_Friendly | 行人友好度 | sidewalk + bench + pedestrian area + street light - barrier - fence |
| Ped_Infra | 步行基础设施质量 | sidewalk + crosswalk + curb cut + pedestrian area + lane marking |
| **ART_Score** | **艺术文化视觉指数** | 0.3×Fascination + 0.25×Being_Away + 0.2×Coherence + 0.25×Ped_Friendly |

#### B.3 人口、POI、用地、路网

- **人口**：`pop_65plus`、`pop_15_59`、`pop_0_14` 栅格采样；`N_UD`（城市密度）= 各年龄组之和
- **POI**：边中点 100m 半径内 `poi_culture`（博物馆/画廊/剧院）、`poi_social`（咖啡馆/广场）、`poi_tech`、`poi_market`、`poi_sport`、`poi_total`
- **用地**：网格 `landuse_shannon`、`green_rate`、`n_types`
- **路网**：`highway_type`、`length`、`maxspeed`、`lanes`，`edge_traffic_pressure` = motor_flag × (lanes/4) × (maxspeed/60) 归一化

#### C.3 一步更新方程（离散化）

**N_UV（城市可玩性指数）**：
```python
N_UV_eq = clip(
    k_cd * N_CD * N_SI     # 文化×街道界面协同
    + k_cr * N_CR          # 认知恢复驱动探索
    + k_ew * N_EW          # 探索意愿正反馈
    + k09 * N09,           # 街道舒适度基础
    0, 1
)
dN_UV = 0.15 * (N_UV_eq - N_UV) - k_crowd * N_UV**2
```

**N_OS（开敞空间嵌入度，外生注入）**：
```python
N_OS = clip(
    (0.4 * GVI + 0.3 * SVF + 0.3 * Shade_Comfort) * log(1 + N_UD_norm),
    0, 1
)
# SVF 不可用时退化为：(0.6 * GVI + 0.4 * Shade_Comfort) * log(1 + N_UD_norm)
```

**N_CB（认知缓冲指数）**：
```python
dN_CB = k_os * N_OS - k_crowd * N_UV * N_CB - k_cb_decay * N_CB
```

**N_CR（认知恢复潜力）**：
```python
dN_CR = (
    k_vc  * N_VC            # 视听复杂性驱动恢复潜力
  - k_cl  * N_CL * N_CR     # 认知负荷抑制恢复
  + k_cb  * N_CB            # 缓冲注入（来自 N_OS）
  + k_hm  * N_HM            # 人机装置直接增益
  - k_cr_decay * N_CR       # 自然衰减
)
```

**N_EW（探索意愿）**：
```python
dN_EW = k16_N_CR * N_CR - k_ew_decay * N_EW
```

**N_CL（认知负荷）**：
```python
N_CL = clip(0.5 * Motor_Pressure + 0.5 * N_TP, 0, 1)
```

**N_PI, N_BD, N_OPT（R_play 可玩接口回路，仅 N_HM > 0）**：
```python
dN_PI = k_pi * N_HM - k_pi_decay * N_PI
dN_BD = k_bd * N_PI - k_b4 * N_HM * N_BD - k_bd_decay * N_BD
dN_OPT = k_opt * N_BD - k_opt_decay * N_OPT
```

### 附录 D：CPVI 详细计算流程

#### D.1 暴露度 E

```python
E_i = normalize(pop_total × (1 + N_CD_norm))
```

| 分量 | 含义 |
|------|------|
| `pop_total` | 路段人口密度（各年龄组之和） |
| `N_CD_norm` | 文化场所密度归一化值 |

#### D.2 敏感性 S

```python
S_i = Motor_Pressure × max(0, 1 - N_OS_norm)
```

#### D.3 适应能力 AC

```python
AC_i = 0.40 * N_OS + 0.35 * N_CD + 0.25 * N09
```

| 分量 | 权重 | 含义 | 对应研究发现 |
|------|------|------|------------|
| N_OS | 0.40 | 开敞空间嵌入度 | 研究发现三（最高权重） |
| N_CD | 0.35 | 文化场所密度 | 研究发现一 |
| N09 | 0.25 | 街道舒适度 | 基础保障 |

**路网连通度调节**：
```python
AC_adjusted = AC * (1 + 0.20 * alpha)
```

#### D.4 可玩资源五维 AC 主导加权

```text
AC_slot = w_cul·U_cul + w_tech·U_tech + w_mkt·U_mkt + w_sport·U_sport + w_traf·U_mob
AC_dom = (AC_OS_W·N_OS + AC_CD_W·AC_slot + AC_N09_W·N09) × (1 + AC_ALPHA_BOOST·α)
```

| 维度 | 边属性 / 数据 | 归一后得 U |
|------|----------------|------------|
| 文化社交 | `poi_culture + poi_social` | U_cul |
| 科技 | `poi_tech` | U_tech |
| 商业 | `poi_market` | U_mkt |
| 体育 | `poi_sport` | U_sport |
| 交通/慢行品质 | `edge_traffic_pressure` + `Ped_Friendly` | U_mob |

**主导预设**（对角 0.52，其余 0.12）：

| 预设键 | 边属性列名 | 语义 |
|--------|------------|------|
| soc_cul | `AC_soc_cul_dom` | 文化主导 |
| tech | `AC_tech_dom` | 科技主导 |
| mkt | `AC_mkt_dom` | 商业主导 |
| sport | `AC_sport_dom` | 体育主导 |
| traf | `AC_traf_dom` | 交通/慢行主导 |

**默认 CPVI 分母 AC**（`cpvi_AC`）= **0.40·N_OS + 0.35·N_CD + 0.25·N09**，不随主导预设改变；五套 `AC_*_dom` 供情景对比与制图导出。

#### D.5 计算流水线

```
步骤 0  加载路网
步骤 1  挂载街景指标（含 ART_Score、GVI、SVF、Shade_Comfort、Motor_Pressure 等）
步骤 2  挂载 POI 分类（poi_culture, poi_social 为核心）
步骤 3  挂载用地网格（landuse_shannon）
步骤 4  挂载人口栅格（pop_65plus, pop_15_59, pop_0_14）
步骤 5  计算车流代理（compute_edge_traffic_pressure）
步骤 6  计算 CLD 节点变量（compute_edge_cld_values）
         → 写入：N_CD, N_SI, N_VC, N_CR, N_OS, N09, N_TP, N_CL, N_UD, N_CB, N06
步骤 7  计算 CPVI 综合得分（compute_edge_cpvi）
         → 写入：cpvi_E, cpvi_S, cpvi_AC, edge_intervention_priority
         → 同时写入五套主导 AC：AC_soc_cul_dom, AC_tech_dom, AC_mkt_dom, AC_sport_dom, AC_traf_dom
步骤 8  导出优先级 DataFrame（edges_to_priority_dataframe）
```

运行 `python scripts/precompute_cld_priority.py` 可提前执行完整流水线，结果保存至 `cache/cld_priority.pkl`。

#### E.3 瓶颈与廊道（`catalyst-seam-clusters.js` + `corridor-bottleneck-routing.js`）

**A. 衔接边（接缝）**

1. **触媒 DBSCAN**：候选 = 激活 ∪ 临界，抽样规则（25% / 至少 20 / cap 200；ε 自 180 m 等）
2. 激活顶点赋簇种；**无权多源 BFS** 染全图
3. **衔接边集** = 两端顶点簇号不同之路网边
4. **退化**：种子不足时回退 k-means k=2 / 经度对半 后再 BFS

**B. 边级改造吸引度 b(e)∈[0,1]**

```
b(e) = 0.45·nPri + 0.35·接缝 + 0.2·脆弱AC
```

**C. 廊道（路径层，簇间可走路径）**

1. 每簇取**几何 medoid 顶点**为接口 T_k
2. 互为最近邻无向对；若不连通则反复加入跨分量最小跳数边（≤ 260 跳）
3. **加权最短路**：边权 `w = 0.55·l̂ + 0.45·(1−b(e))`；已出现过的边叠加占用惩罚（γ=0.35）
4. **输出**：`field_system_selection.html` 用玫红实线折线绘路径；`xujiahui-site-selection.html` 不绘该层
